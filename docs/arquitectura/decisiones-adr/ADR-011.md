# ADR-011: Manejo del conflicto del puerto 19723 (AutoClaw vs ArchiCAD Live Connection)

## Estado
Aprobado

## Contexto
Existe un conflicto conocido entre AutoClaw (escritorio) y la Live Connection de Grasshopper-ArchiCAD por el uso del puerto 19723.
AutoClaw escribe en forma hardcodeada el puerto 19723 y lo reclama tras un período de inactividad de Grasshopper/ArchiCAD.
La Live Connection de Grasshopper solo puede conectar por el puerto 19723 para operar el canvas (inyección BIM nativa).
Aunque la API JSON/Python de ArchiCAD (Tapir) puede usar un rango de puertos (19723-19743), en la práctica únicamente el puerto 19723 funciona adecuadamente para la conexión básica entre Grasshopper y ArchiCAD.
Este conflicto impide la ejecución de las etapas que requieren la conexión ArchiCAD (C4-ArchiCAD, C5, F5-MAPEO) si AutoClaw está activo y reclama el puerto.

## Decisión
Durante las sesiones de trabajo que involucren la conexión Grasshopper-ArchiCAD (etapas C4, C5, F5-MAPEO y cualquier otra que requiera Live Connection/Tapir con el gateway AutoClaw activo):
1. **No iniciar AutoClaw** mientras se esté trabajando en la conexión Grasshopper-ArchiCAD, a menos que sea absolutamente necesario para otras tareas no relacionadas con el puente Geométrico BIM.
2. Si por alguna razón es necesario abrir AutoClaw durante dicha sesión, entonces:
   a. Después de usar AutoClaw, cerrar todos los programas relacionados (AutoClaw, Grasshopper, ArchiCAD).
   b. Volver a iniciar los programas en el siguiente orden: ArchiCAD → Grasshopper → AutoClaw (para asegurar que ArchiCAD y Grasshopper obtengan el puerto 19723 antes de que AutoClaw lo reclame).
   c. Verificar que la conexión Live Connection/Tapir esté activa antes de continuar con el trabajo en Grasshopper-ArchiCAD.
3. Este procedimiento se documentará en el manual de ejecución y se considerará una tarea operativa del usuario, no una falla del sistema.

## Consecuencias
### Positivas
- Evita el bloqueo del puerto 19723 durante las operaciones críticas de conexión Grasshopper-ArchiCAD.
- Permite la ejecución de las etapas S3 que dependen de ArchiCAD (C4, C5, F5-MAPEO) sin intervención compleja de reconfiguración de puertos.
- Reduce la necesidad de cambios de configuración en el sistema, evitando riesgos de incompatibilidad.

### Negativas
- Requiere disciplina del operador para recordar no abrir AutoClaw durante las sesiones de trabajo en el puente BIM.
- En caso de que se necesite AutoClaw, implica un reinicio de las aplicaciones, lo que puede interrumpir el flujo de trabajo.
- No resuelve el problema de fondo (el hardcodeo de AutoClaw), pero lo mitiga mediante un procedimiento operativo.

### Neutrales
- Tapir (API JSON de ArchiCAD) sigue funcionando independientemente en otros puertos, por lo que las tareas que solo requieran la API (por ejemplo, F3_StorySync) no se ven afectadas.
- El resto del pipeline (Fases 1-3, excepto la inyección BIM) continúa operando normalmente.

## Relación con otros documentos

- Es un prerequisito para las etapas **C4-ArchiCAD**, **C5** y **F5-MAPEO**.
- Se menciona en el **MANUAL_DE_EJECUCION.md** bajo la sección de procedimientos operativos.
